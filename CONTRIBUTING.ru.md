# Публикация плагина AngelOS

[English](CONTRIBUTING.md) | [Русский](CONTRIBUTING.ru.md)

Это руководство описывает разработку плагина, локальную проверку, выпуск ZIP и
подачу заявки в Community Registry.

## 1. Создайте плагин

Храните плагин в отдельном репозитории. Минимальная структура:

```text
my-widget/
├── manifest.json
├── Main.qml
├── Settings.qml
└── README.md
```

Для разработки скопируйте каталог в пользовательскую папку плагинов:

```bash
mkdir -p ~/.config/angelos/plugins
cp -a my-widget ~/.config/angelos/plugins/my-widget
```

Следуйте реальным соглашениям AngelOS и переиспользуйте его компоненты. Не
копируйте весь AngelOS и не создавайте собственный загрузчик плагинов.

## 2. Создайте `manifest.json`

Обязательные поля manifest:

```json
{
  "id": "my-widget",
  "name": "My Widget",
  "version": "1.0.0",
  "author": "Ваше имя",
  "description": "Краткое описание.",
  "icon": "sparkles",
  "enabledByDefault": true,
  "main": "Main.qml",
  "settings": "Settings.qml"
}
```

`id` должен быть уникальным, стабильным и состоять из строчных латинских букв,
цифр, `-` или `_`. После публикации не меняйте его. `version` используется для
обнаружения обновлений; используйте формат `MAJOR.MINOR.PATCH`, например
`1.0.0`.

Объявляйте только реально существующие точки входа. AngelOS использует поля
`main`, `barWidget`, `launcher`, `settings` и `menu`. Все указанные файлы должны
находиться внутри каталога плагина. Не используйте абсолютные пути и не
скачивайте и не запускайте код при открытии плагина.

## 3. Проверьте локально

Проверьте JSON и обязательные поля:

```bash
jq empty my-widget/manifest.json
jq -e '.id and .name and .version' my-widget/manifest.json
```

Скопируйте плагин в пользовательский каталог, перезагрузите AngelOS и проверьте
его в **Settings -> Plugins**. Проверьте основную функцию, настройки,
включение/выключение и обработку ошибок. Запишите необходимые программы,
сетевой доступ, разрешения и состояние авторизации.

## 4. Создайте ZIP

В архиве должен быть ровно один `manifest.json`: в корне ZIP или на один каталог
ниже. Его `id` и `version` должны совпадать с записью registry.

Пример архива с manifest в корне:

```bash
cd my-widget
zip -r ../my-widget-v1.0.0.zip manifest.json Main.qml Settings.qml README.md
```

Добавьте все QML, JavaScript, изображения и вспомогательные файлы, нужные во
время работы. Не включайте `.git`, секреты, кэш сборки и посторонние файлы.

Проверьте архив:

```bash
unzip -t ../my-widget-v1.0.0.zip
unzip -l ../my-widget-v1.0.0.zip
```

Community Store отклоняет повреждённые архивы, небезопасные пути, symlink,
невалидный manifest, несовпадающие ID/версии и файлы сверх установленных лимитов.

## 5. Опубликуйте GitHub Release

Создайте публичный GitHub-репозиторий плагина и отправьте туда исходники.
Создайте tag и release с ZIP-файлом:

```bash
git tag v1.0.0
git push origin v1.0.0
gh release create v1.0.0 ../my-widget-v1.0.0.zip \
  --title "My Widget 1.0.0" \
  --notes "Первый выпуск"
```

URL asset будет выглядеть так:

```text
https://github.com/you/my-widget/releases/download/v1.0.0/my-widget-v1.0.0.zip
```

Ссылка должна быть HTTPS и доступна без GitHub-авторизации.

## 6. Подайте заявку в registry

Сделайте fork registry и добавьте запись в `plugins.json` со статусом `pending`:

```json
{
  "id": "my-widget",
  "name": "My Widget",
  "author": "Ваше имя",
  "version": "1.0.0",
  "description": "Что делает плагин.",
  "source": "https://github.com/you/my-widget/releases/download/v1.0.0/my-widget-v1.0.0.zip",
  "repository": "https://github.com/you/my-widget",
  "tags": ["widgets", "utility"],
  "category": "Utilities",
  "license": "MIT",
  "dependencies": [],
  "permissions": [],
  "status": "pending"
}
```

Откройте Pull Request и опишите назначение плагина, версии AngelOS, на которых
он проверялся, ссылки на исходники и release, лицензию и атрибуцию, зависимости,
сетевые обращения и нужные разрешения. Добавьте скриншот, если он помогает
оценить интерфейс.

Записи `pending` не показываются в Store. Сопровождающий проверяет код,
manifest, архив, происхождение, лицензию, зависимости и совместимость. Только
после этого статус меняется на `approved`.

## 7. Выпустите обновление

Измените версию, проверьте плагин, создайте новый release asset и отправьте
изменение registry с прежним `id` и новыми `version` и `source`. Не используйте
старый номер версии для другого содержимого.

Пользователи могут обновить список клавишей `r` в TUI Store и нажать `Enter` на
плагине с обновлением.

## 8. Снятие публикации и безопасность

Чтобы скрыть запись, измените `approved` на `pending` или удалите её из registry.
Не одобряйте непроверенный код. QML и вспомогательные программы запускаются с
правами пользователя; registry не изолирует их.

## Категории для AngelOS

Market 0.8.0 группирует фильтры в «Сюжет и игра», «Оформление», «Плагины и инструменты». Категории учитывают уже существующие возможности AngelOS: рай и ад с кругами, визуальную новеллу, персонажей, сцены и голоса; палитры, скины интерфейса, обои, курсоры, шрифты, значки и эффекты.

| `category` | В магазине |
| --- | --- |
| `Story` | Сюжет |
| `Novels` | Визуальные новеллы |
| `Quests` | Квесты |
| `Characters` | Персонажи |
| `Realms` | Миры и измерения |
| `Dialogue` | Диалоги и сцены |
| `Minigames` | Мини-игры |
| `Voices` | Голоса и озвучка |
| `Pets` | Питомцы |
| `Widgets` | Виджеты |
| `Desktop` | Рабочий стол |
| `Bar` | Панель |
| `Themes` | Оформление |
| `Skins` | Скины интерфейса |
| `Wallpapers` | Обои |
| `Cursors` | Курсоры |
| `Fonts` | Шрифты |
| `Icons` | Значки |
| `Effects` | Эффекты и анимации |
| `AI` | AI-помощники |
| `DeveloperTools` | Разработка |
| `Launcher` | Лаунчер и поиск |
| `Network` | Сеть |
| `Audio` | Музыка и звук |
| `Productivity` | Продуктивность |
| `Integrations` | Интеграции |
| `Accessibility` | Доступность |
| `System` | Система |
| `Utilities` | Утилиты |

В `category` укажи один основной ID из таблицы. В `tags` можно перечислить другие подходящие категории. Названия в реестре остаются стабильными английскими ID, магазин переводит подписи. Прежние категории и теги работают; `Worlds`, `Narrative`, `Lore` и `story-packs` также распознаются. Неизвестная категория автоматически добавляется в список «Плагины и инструменты».

«Сюжет» собирает истории, новеллы, квесты, персонажей, миры, диалоги и голоса. Обычные питомцы и мини-игры не становятся сюжетными без сюжетного тега. «Оформление» объединяет его подкатегории. Поиск понимает русские и английские названия категорий.

Пример сюжетного пакета:

```json
"category": "Story",
"tags": ["story", "novel", "dialogue", "characters", "heaven"]
```

Пример пакета внешнего вида:

```json
"category": "Skins",
"tags": ["skins", "themes", "fonts", "cursor"]
```

Категория описывает содержимое пакета и служит фильтром. Она сама по себе не подключает главы, сцены или голоса к сюжетному движку: автор плагина реализует это через доступные API AngelOS и указывает совместимость и зависимости.
